# Shadowverse WB Memo: Issueを育てる

## 目的

曖昧な依頼を急いでチケット化せず、必要な対話を通じて、実行・レビュー・完了判断が
できるIssueへ育てる。ユーザーの入力回数を減らすことではなく、判断に不要な編集作業を
引き受けることを目標にする。

## 進め方

1. `README.md`、`AGENTS.md`、`DEVELOPMENT.md`、関連Issue・文書を読む。
2. 背景、達成したい価値、解決したい問題を確認する。
3. 受け入れ条件、対象外、後戻りが大きい制約を、必要なだけ対話して明確にする。
4. 選択肢がある場合は、結論を決め打ちせず、比較と判断材料を示す。
5. 目的、必要ならユーザーストーリー、受け入れ条件、対象外、制約・関連情報、推奨ラベル、
   推奨StatusからなるIssue下書きを提示する。

製品・設計・優先順位の判断を、質問を避けるためだけに補完してはならない。一方で、
表現の整理や明らかな重複の除去のためだけに質問を増やしてはならない。

## 作成と分割

ユーザーが下書きを明示的に承認し、作成を許可した場合だけ作成する。GitHub操作には
リポジトリの `Makefile` を使い、外部変更には必ず `CONFIRM=1` を付ける。

独立して実装・検証・レビュー・PR化する価値がある作業は、親Issueと子Issueに分ける案を
提示できる。単なる手順は親Issueのチェックリストに留める。分割時は、親子の責務、依存、
各Issueの完了条件を示し、ユーザーの確認後に `make subissue-create` を使う。

作成後はIssue番号、URL、付与ラベル、ProjectのStatusを報告する。
